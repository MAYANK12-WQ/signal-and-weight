Why this matters

Low degree ignores the pattern (underfitting). Very high degree memorizes the noise in these exact 18 points instead of the shape underneath (overfitting) — training error drops to near zero while error on new points climbs back up. The sweet spot is wherever test error is lowest, not where training error is lowest.

Leave the ball where it starts, on the left, and run it. With a small-to-medium learning rate it settles into that shallower dip near x≈-1.7 (a local minimum) and stays there — pure gradient descent only ever looks at the slope right under its feet, so it has no way to know a truly lower point exists near x≈1.76 on the right (the global minimum). Now crank the learning rate all the way up: a big enough step can accidentally leap over the hump in between and land closer to the real minimum — which shows why "just raise the learning rate" isn't a real fix, it's a gamble.

Exhibit 03 · often confusing

Inside a Neuron

A neuron multiplies each incoming number by a weight, adds them up, and squashes the result through an activation function. Drag the two inputs. Drag up or down directly on any connecting line to change its weight and watch every downstream neuron react.

Forward passactivation: sigmoid
Network output
–
What you're seeing

Every line is a weight; its thickness is the weight's size and its color shows the sign — teal strengthens, rust weakens. Every circle is a neuron; brighter fill means it fired more strongly. Training a network is nothing more than automatically adjusting every one of these weights until the output matches what you wanted — the same drag you just did by hand, done by gradient descent instead.

Breaking Language Into Pieces

Before a model can read text, the text has to become numbers. The first step is chopping a sentence into tokens — sometimes whole words, sometimes word fragments. Type anything below.

Switch to subword mode and type a long or unusual word like "antidisestablishmentarianism" or a made-up one like "blorptastic". The model has never seen the whole word before, but it has seen small pieces of it — so it reads the piece it recognizes and reasons about the rest fragment by fragment, exactly like sounding out a word you've never read. Honesty check: this demo splits words using a small hand-written list of prefixes and suffixes, so you can see the idea clearly. A real tokenizer (like BPE, used by GPT-style models) doesn't use hand-written rules at all — it statistically learns a fixed vocabulary of ~30,000-100,000 pieces by scanning huge amounts of text for the most common repeated chunks.

Exhibit 05 · often confusing

Meaning as Coordinates

Once text is tokens, each token gets converted into a list of numbers — a point in space — called an embedding. Words with related meaning end up near each other. Real embeddings use hundreds of numbers per word; this toy version uses two, so you can see it plotted directly. Click a word, or drag it somewhere new.

Toy embedding space (2 dimensions)click a point
Nearest neighbors
  • Select a word to compare
Why this matters

Nobody hand-writes these coordinates. A model learns them by reading huge amounts of text and noticing which words tend to appear in similar situations — "cat" and "dog" show up in similar sentences, so they drift close together, entirely on their own.

Exhibit 06 · the payoff

Putting It Together: Attention

This is how the ideas above combine inside something like GPT: tokenize the sentence, look up each token's embedding, then have every token compare itself to every other token to decide what to focus on. Click a word to see where it's looking.

Self-attention (simplified, 4-dimensional teaching model)
    This token's blended result, after attention
    Reading the picture

    Each token is turned into three different vectors: a Query (what it's looking for), a Key (what it advertises about itself), and a Value (what it actually hands over if picked). Attention weight between two tokens is just how well one's Query matches another's Key; the bar chart above appears once you select a token and shows its new, blended Value vector — a mix of everyone it attended to. Also notice the two "the"s can still attend differently, because this demo adds a small positional signal to each embedding first, exactly like a real transformer does — otherwise identical words at different spots in the sentence would be mathematically indistinguishable. This is a simplified teaching version of the mechanism using fixed, hand-picked projections instead of ones learned from data — a real transformer learns its Q/K/V projections and runs many attention "heads" in parallel across hundreds of dimensions. For a beautifully detailed, real-weights version of this exact idea, see the Transformer Explainer project, which inspired this exhibit.

    Seeing in Patches

    Images are grids of numbers (brightness values), and a convolutional network scans a small grid of learned numbers — a kernel — across every position, looking for one specific pattern. Pick a preset or type your own numbers and watch the output image change.

    Click or drag on the input image to draw your own shape.

    What you're seeing

    This single kernel only knows how to look for one thing. A real CNN stacks dozens of kernels per layer and dozens of layers — early layers learn simple things like edges (exactly like the one here), and later layers combine those into eyes, wheels, or whatever the network needs to recognize. Nobody hand-picks these numbers in a real network; they're learned by gradient descent, same as every other weight on this page.

    Exhibit 09

    Training vs. Prompting

    If you've used a chatbot, you've already changed its behavior by typing instructions — so why does anyone bother with the expensive part? Toggle between the two to see what each one actually changes.

    Millions of examples
    →
    Gradient descent(hours-to-weeks, needs a GPU)
    →
    Every weight in the network changes, permanently

    Training is exactly Exhibits 02 and 03, done automatically, at enormous scale: millions of examples, each one nudging every weight a tiny amount. The result is baked into the model's parameters — it doesn't forget it between conversations, and it applies to every future user, forever, until someone trains it again.

    Your typed instructions
    →
    One forward pass(seconds, no training happens)
    →
    Zero weights change — only this conversation is affected

    Prompting doesn't touch a single weight — it just hands the frozen, already-trained network some extra context to read before it answers, the same way giving a person a reference sheet changes what they say without changing what they know. Close the conversation and the effect disappears completely; the model that greets the next user is byte-for-byte identical.

    Why this matters

    This is why you can't fix a chatbot's factual gaps just by asking nicely, but you also don't need a GPU cluster to make it follow a new tone or format. Fine-tuning sits in between: it's real training (weights genuinely change) but starting from an already-trained model on a much smaller, cheaper dataset.
